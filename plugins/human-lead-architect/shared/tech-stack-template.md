# Tech stack document

Shared by `tech-stack-reverse-engineer` and `tech-stack-add`.

## Location

Use the existing file if there is one (`docs/architecture/tech-stack.md`, `docs/tech-stack.md`, `TECH-STACK.md`, or a path the user names). Otherwise create `docs/architecture/tech-stack.md`.

## Ownership

The file has 2 kinds of content:

- **Generated** (between the `generated:tech-stack` markers): what the code proves today. Only `tech-stack-reverse-engineer` writes it, and every row cites evidence.
- **Human-owned** (everything else): the Planned section that `tech-stack-add` maintains, and any notes people write. No skill rewrites a human note.

## Format

```markdown
# Tech stack

{One or two sentences a person wrote about the system. Leave a `{TODO: describe the system}` if empty.}

<!-- generated:tech-stack:begin -->
_Scanned {YYYY-MM-DD} at commit `{short sha}`. Generated by tech-stack-reverse-engineer: edit outside the markers._

## Deployable units

| Unit | Type | Language / runtime | Path |
|---|---|---|---|
| {name from the repo} | {API, worker, web app, function, library} | {e.g. `C#` / `net8.0`} | `{path}` |

## Technologies

| Layer | Technology | Version | Used by | Evidence | Decision |
|---|---|---|---|---|---|
| {layer} | {name} | {version or `unpinned`} | {units} | `{file:line}` | {[ADR 001](path) or `no ADR` or `n/a`} |

Layers, in this order, skipping empty ones: Languages and runtimes, Backend frameworks, Frontend, Data stores, Messaging and integration, Identity and security, Infrastructure and hosting, CI/CD, Observability, Testing.

Test projects and shared libraries are not deployable units: list their frameworks under Testing or with the unit that uses them.

List libraries only when they shape the architecture (ORM, messaging library, web framework, DI or mediator framework, test framework). Leave out utilities.

## Findings

- **Missing decisions:** {significant technologies with `no ADR`}
- **Unverified:** {things suspected but not proven, marked `?`}

|---|---|---|---|---|---|---|

## Notes

{Free text owned by the team.}
```

## Writing rules

- Plain prose, no emoji, digits for numbers.
- Tables: one technology per row, concrete values, `code` for versions and paths.
- Never copy secrets, hosts or credentials from config into the document.
