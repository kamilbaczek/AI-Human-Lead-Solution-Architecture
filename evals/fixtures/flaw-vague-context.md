# ADR 014: Move to microservices

## Status
Proposed

## Date
2026-09-05

## Context
The current system is old and hard to work with. Microservices are the modern way to build
software and will make everything better.

## Decision
We will migrate the platform to microservices.

## Consequences

### Positive
- Better scalability.
- Better maintainability.
- Teams can move faster.

### Negative
- More services to manage.

### Risks
- Some complexity.

## Alternatives Considered

### Alternative 1: Status Quo / Do Nothing
- **Why not chosen:** The current system is too hard to work with.

### Alternative 2: Modular monolith
- **Why not chosen:** Not as good as microservices.
